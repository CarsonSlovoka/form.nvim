*form.txt*    Native snippet forms with write-time validation

===============================================================================
1. Introduction                                                 *form.nvim*

form.nvim creates a virtual form buffer. Native vim.snippet handles input,
and BufWriteCmd implements :write as validation followed by submission.
Validation is independent of the snippet session. No dependencies required.

Requires Neovim 0.12+. No setup() call is needed.

===============================================================================
2. API                                                           *form.open()*

require('form').open(spec) -> bufnr

Call from Normal mode. Options:

    title         string, default 'form'
    fields        ordered non-empty list of field definitions
    window        'split' (default), 'vsplit', or 'current'
    path          optional default local output path, absolute at open time
    format        'raw' (default), 'json', or function(data, ctx)
    validate      function(data) -> nil or { field = message }
    on_submit     function(data, ctx) -> nil or false, message
    mappings      boolean, default true; buffer-local Tab and Shift-Tab
    diagnostic    table of vim.diagnostic display options
    notify        boolean, default true

Fields:

    name          required unique key; _form is reserved
    label         display label, defaults to name
    type          'string' (default), 'number', 'integer', 'boolean'
    required      boolean, default false
    default       single-line scalar initial value
    min, max      inclusive bounds for numeric fields
    validate      function(value) -> true or false, message

Example: >lua
    require('form').open({
      title = 'location',
      fields = {
        { name = 'longitude', type = 'number',
          min = -180, max = 180, required = true },
        { name = 'latitude', type = 'number',
          min = -90, max = 90, required = true },
        { name = 'description', required = true },
      },
      format = 'json',
    })
<
The input is trimmed, optional empty fields are omitted, and numeric/boolean
values are converted before submission. Form-level validation runs after
field-level validation succeeds. Use _form for a general error.

===============================================================================
3. Writing                                                       *form-write*

:w                  Validate and submit, using path if configured.
:w ~/location.json  Validate and export to the specified destination.
:w! ~/location.json Validate and allow replacement of an existing regular file.
:wq ~/location.json Validate, write, and close the window on success.

Explicit paths override the default for one write only. The form retains its
virtual buffer name. Without a path or callback, :w only validates.

Output formats:                                                  *form-format*
    raw     Original buffer lines, including labels and whitespace.
    json    JSON object of validated, typed values.
    function(data, ctx) -> string or dense string[]
            Custom output. Lines are joined with LF and a final LF;
            an empty list produces an empty file. A string is given a
            trailing LF if missing.

The built-in writer uses UTF-8 and LF. Filename extensions do not select a
format. The parent directory must exist. Output is staged in a temporary file
in that directory; exclusive creation uses a hard link and forced replacement
uses rename. Existing non-regular destinations (including symlinks) are
rejected. See README.md for filesystem and permission details.

Custom submission:                                               *form-submit*

If on_submit is set, it replaces built-in serialization and persistence.
The callback receives validated data and a context table:

    bufnr     form buffer number
    title     form title
    path      effective absolute local file path, or nil
    force     true if the write command used !

The custom serializer receives the same context. The callback owns all
persistence and overwrite checks. Returning false, message or raising an
error rejects submission. Other normal returns mean success. Both callback
and serializer must be synchronous and must not modify/delete the form buffer.

Successful submission clears diagnostics and resets 'modified'. Any failure
raises a write error and retains 'modified'. :w! never bypasses validation.
:wq closes on success; failed writes should leave the form open. Use :bd! to
discard a pending buffer. Diagnostics update on write only. Repeated :w
commands submit again. Global 'autowrite' and 'autowriteall' can initiate
submission. :update and :x may skip unmodified buffers.

One line per field, fixed schema order. Multiline values, partial writes,
append and :saveas workflows are not supported. External :write !command
is not form submission. See README.md and README.zh_TW.md for details.
