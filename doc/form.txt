*form.txt*    Native snippet forms with write-time validation

===============================================================================
1. Introduction                                                 *form.nvim*

form.nvim creates a virtual form buffer. Native vim.snippet handles input,
and BufWriteCmd implements :write as validation followed by submission.
Validation is independent of the snippet session. Forms with multiline
fields use independent Extmark label anchors. No dependencies required.

Requires Neovim 0.12+. No setup() call is needed.

===============================================================================
2. API                                                           *form.open()*

require('form').open(spec) -> bufnr

Call from Normal mode. Options:

    title         string, default 'form'
    fields        ordered non-empty list of field definitions
    window        'split' (default), 'vsplit', or 'current'
    path          optional default local output path, absolute at open time
    format        'raw' (default), 'json', or function(data, ctx)
    validate      function(data) -> nil or { field = message }
    on_submit     function(data, ctx) -> nil or false, message
    mappings      boolean, default true; buffer-local Tab and Shift-Tab
    diagnostic    table of vim.diagnostic display options
    notify        boolean, default true

Fields:

    name          required unique key; _form is reserved
    label         display label, defaults to name
    type          'string' (default), 'number', 'integer', 'boolean'
    required      boolean, default false
    multiline     boolean, default false; string fields only
    default       single-line scalar, or multiline string (LF and tab allowed)
    min, max      inclusive bounds for numeric fields
    validate      function(value) -> true or false, message

Example: >lua
    require('form').open({
      title = 'location',
      fields = {
        { name = 'longitude', type = 'number',
          min = -180, max = 180, required = true },
        { name = 'latitude', type = 'number',
          min = -90, max = 90, required = true },
        { name = 'description', required = true, multiline = true },
      },
      format = 'json',
    })
<
Single-line values are trimmed; nonblank multiline strings retain their exact
whitespace and newlines. Empty or whitespace-only optional fields are omitted.
Numeric/boolean values are converted before submission. Form-level validation runs after
field-level validation succeeds. Use _form for a general error.

Multiline fields:                                             *form-multiline*

A multiline string uses a separate label line followed by its value lines: >
    Title: Hello
    Description:
    First line
      Second line
    Author: Admin
<
Set multiline = true in a string field definition. The label is anchored by
an independent Extmark; the next label or end of buffer determines its value
range. Label-like text in a value is not parsed as a field. Keep all labels
intact and in schema order, at the start of their lines. In a mixed form,
single-line fields must retain the exact label prefix and stay on one line.
Keep at least one value line for every multiline field, even when empty.

Use ordinary Insert/Normal mode editing. Structural errors update on text
changes (display in Insert mode follows diagnostic.update_in_insert). User
validators still run only on write. Undo/Redo restores/updates label anchors;
use Undo for accidentally deleted or replaced labels, rather than recreating
them by hand. Initial expansion is not an undoable edit. Do not replace the
whole mixed-form buffer. Snippet navigation still uses native vim.snippet;
when the session ends, range tracking and submission remain independent.
Forms with only single-line fields keep the original line-based parser.

===============================================================================
3. Writing                                                       *form-write*

:w                  Validate and submit, using path if configured.
:w ~/location.json  Validate and export to the specified destination.
:w! ~/location.json Validate and allow replacement of an existing regular file.
:wq ~/location.json Validate, write, and close the window on success.

Explicit paths override the default for one write only. The form retains its
virtual buffer name. Without a path or callback, :w only validates.

Output formats:                                                  *form-format*
    raw     Original buffer lines, including labels and whitespace.
    json    JSON object of validated, typed values.
    function(data, ctx) -> string or dense string[]
            Custom output. Lines are joined with LF and a final LF;
            an empty list produces an empty file. A string is given a
            trailing LF if missing.

The built-in writer uses UTF-8 and LF. Filename extensions do not select a
format. The parent directory must exist. Output is staged in a temporary file
in that directory; exclusive creation uses a hard link and forced replacement
uses rename. Existing non-regular destinations (including symlinks) are
rejected. See README.md for filesystem and permission details.

Custom submission:                                               *form-submit*

If on_submit is set, no serialization or persistence happens automatically.
The callback receives validated data and a context table:

    bufnr     form buffer number
    title     form title
    path      effective absolute local file path, or nil
    force     true if the write command used !
    serialize()  return the configured serialized string, even without a path
    write()      write that string to the resolved path; return true on success
                 or raise an error (including a missing path)

For example: >lua
    format = 'json',
    on_submit = function(data, ctx)
      local content = ctx.serialize()
      ctx.write()
      vim.fn.setreg('+', content)
    end,
<
Call the helpers without arguments. The first successful serialization is
cached for the current submission, including an empty string. Failed
serialization is not cached. Each new submission uses a fresh cache.
ctx.write() preserves the resolved path, bang flag, and built-in overwrite
checks. Repeated calls perform separate writes. Neither helper is invoked
implicitly by a custom on_submit. Without a callback and with a destination,
the default writer uses the same helpers.

The custom serializer receives the same context. Do not call the helpers
recursively from the format function or after the submission has ended.
Returning false, message or raising an error rejects submission. Other
normal returns mean success. Both callback and serializer must be synchronous
and must not modify/delete the form buffer. External side effects cannot be
rolled back if a callback subsequently fails.

Successful submission clears diagnostics and resets 'modified'. Any failure
raises a write error and retains 'modified'. :w! never bypasses validation.
:wq closes on success; failed writes should leave the form open. Use :bd! to
discard a pending buffer. Value diagnostics update on write only; mixed forms
also report structural errors during editing. Repeated :w
commands submit again. Global 'autowrite' and 'autowriteall' can initiate
submission. :update and :x may skip unmodified buffers.

Fixed schema order. Single-line and multiline string fields are supported.
Partial writes, append and :saveas workflows are not supported. External :write !command
is not form submission. See README.md and README.zh_TW.md for details.
